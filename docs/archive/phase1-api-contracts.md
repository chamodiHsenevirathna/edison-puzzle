# API contracts (proposed)

> **Proposal only.** The backend is not implemented. All example JSON below was **generated by the real
> engine** (`to_dict()`), so field names and shapes are accurate; HTTP status codes, limits and
> error codes are design decisions that still need implementing and testing.
> TypeScript equivalents: [`shared/types/api.ts`](../../shared/types/api.ts), [`edison.ts`](../../shared/types/edison.ts).

Conventions: JSON, camelCase, base path `/api`. Coordinates `(0,0)` top-left; x right, y down; units are board cells.

**Errors** use one envelope:

```json
{ "error": { "code": "puzzle_not_found", "message": "No puzzle with id 'x'", "details": [] } }
```

| HTTP | `code` | When |
|---|---|---|
| 404 | `puzzle_not_found` | unknown `puzzle_id` |
| 422 | `invalid_request` | body fails schema validation (types, missing fields) |
| 422 | `invalid_puzzle` | semantically invalid config (non-positive size, duplicate ids, …) |
| 422 | `limit_exceeded` | board/piece count above server limits |
| 429 | `solver_busy` | concurrent-solve cap reached |

A puzzle that has no solution, or an invalid arrangement, is **not** an error: it is a 200 with data saying so.

---

## GET `/api/puzzles`

200:

```json
{
  "puzzles": [
    { "id": "edison-original", "name": "Edison Puzzle (original)",
      "board": { "width": 56, "height": 56 }, "pieceCount": 12,
      "allowRotation": true, "builtIn": true }
  ]
}
```

## GET `/api/puzzles/{puzzle_id}`

200: a full puzzle plus derived fields. 404 `puzzle_not_found`.

```json
{
  "id": "edison-original",
  "name": "Edison Puzzle (original)",
  "board": { "width": 56, "height": 56 },
  "pieces": [
    { "id": "r01", "width": 28, "height": 14 },
    { "id": "r02", "width": 21, "height": 18 }
  ],
  "allowRotation": true,
  "builtIn": true,
  "piecesArea": 3136,
  "boardArea": 3136,
  "areaBalanced": true
}
```
(`pieces` abbreviated here; the original has 12.)

## POST `/api/puzzles`

Request (`id` on pieces optional; server assigns `r01`, `r02`, … when omitted; `allowRotation` defaults to `true`):

```json
{
  "name": "Two dominoes",
  "board": { "width": 2, "height": 2 },
  "pieces": [ { "width": 1, "height": 2 }, { "width": 1, "height": 2 } ],
  "allowRotation": true
}
```

201: the created puzzle in the `GET /api/puzzles/{id}` shape (`builtIn: false`, server-assigned `id`).
422 `invalid_puzzle` / `limit_exceeded` / `invalid_request`.
An area-mismatched puzzle is accepted; it reports `areaBalanced: false` and solves to `not_solvable`.

## POST `/api/puzzles/{puzzle_id}/solve`

Request (every field optional):

```json
{
  "maxSolutions": 1,
  "events": "none",
  "maxNodes": 2000000,
  "timeLimitSeconds": 10,
  "maxEvents": 20000
}
```

| Field | Default | Meaning |
|---|---|---|
| `maxSolutions` | `1` | `null` = find all (still bounded by limits) |
| `events` | `"none"` | `"milestones"` = started/solution/completed only; `"full"` = every step event |
| `maxNodes`, `timeLimitSeconds` | server defaults | clamped to server hard caps |
| `maxEvents` | `20000` | only for `"full"`; truncates and sets `eventsTruncated` |

200, `status` is one of `exhausted`, `max_solutions`, `node_limit`, `time_limit`, `not_solvable`. Real output for a 2×2 board with two 1×2 dominoes, `events: "milestones"` (`elapsedMs` normalised):

```json
{
  "puzzleId": "two-dominoes",
  "status": "max_solutions",
  "solutions": [
    { "puzzleId": "two-dominoes",
      "placements": [
        { "pieceId": "p1", "x": 0, "y": 0, "width": 1, "height": 2, "rotated": false },
        { "pieceId": "p2", "x": 1, "y": 0, "width": 1, "height": 2, "rotated": false } ] }
  ],
  "metrics": { "nodesVisited": 3, "placementsAttempted": 2, "placementsAccepted": 2,
               "placementsRejected": 0, "backtracks": 0, "solutionsFound": 1,
               "maxDepth": 2, "elapsedMs": 0.1 },
  "events": [
    { "type": "solver_started", "seq": 0, "puzzle": { "...": "full puzzle" }, "maxSolutions": 1, "trace": false },
    { "type": "solution_found", "seq": 1, "solutionIndex": 0, "solution": { "...": "as above" } },
    { "type": "search_completed", "seq": 2, "status": "max_solutions", "solutionsFound": 1,
      "metrics": { "...": "as above" }, "message": null }
  ],
  "eventsTruncated": false
}
```

With `events: "full"` the same run produces, in order: `solver_started`, `piece_selected`, `placement_attempted`, `placement_accepted`, `piece_selected`, `placement_attempted`, `placement_accepted`, `solution_found`, `search_completed`. A step event looks like:

```json
{ "type": "placement_accepted", "seq": 3, "depth": 0,
  "placement": { "pieceId": "p1", "x": 0, "y": 0, "width": 1, "height": 2, "rotated": false },
  "placements": [ { "pieceId": "p1", "x": 0, "y": 0, "width": 1, "height": 2, "rotated": false } ],
  "remaining": ["p2"] }
```

Event semantics (what is inside `placements` for each type) are in [algorithm-design.md](../algorithm-design.md#execution-events).

Notes:
* The original puzzle solves in ~15 ms for one solution; enumerating all (8) takes ~65 s and would exceed the proposed request limits (`time_limit` is returned with whatever was found).
* A solution's placements are in the order the solver placed them. Interchangeable pieces get ids in config order.
* `not_solvable` (area mismatch) returns `solutions: []` with `message` set; `exhausted` with `solutions: []` means a complete search found none.

## POST `/api/puzzles/{puzzle_id}/validate`

Request:

```json
{ "placements": [
    { "pieceId": "p1", "x": 0, "y": 0, "width": 1, "height": 2, "rotated": false },
    { "pieceId": "p2", "x": 0, "y": 0, "width": 1, "height": 2, "rotated": false } ] }
```

200, real engine output for that request against the two-domino puzzle:

```json
{
  "valid": false,
  "errors": [
    { "code": "overlap", "message": "pieces 'p1' and 'p2' overlap at (0,0)", "pieceId": "p2" },
    { "code": "uncovered_cells", "message": "2 board cell(s) are not covered" }
  ]
}
```

All problems are reported, not just the first. A fully correct tiling returns `{ "valid": true, "errors": [] }`.
Error codes: `unknown_piece`, `duplicate_piece`, `missing_piece`, `dimension_mismatch`, `rotation_not_allowed`, `rotation_flag_mismatch`, `out_of_bounds`, `overlap`, `uncovered_cells`.

## Deferred (not in this contract)

* `POST …/solve/stream`: server-sent events from the engine's lazy generator.
* `GET …/solutions`: persisted/cached solutions.
* `DELETE /api/puzzles/{id}`, puzzle editing.
